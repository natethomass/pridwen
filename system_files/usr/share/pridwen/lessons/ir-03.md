# Contain and account

Once you understand enough, containment stops the situation from spreading
without destroying what you have preserved. The cleanest containment for a
networked host is to cut it off the network while leaving it running, so that
its memory, processes and connections remain for study. Powering it off would
stop the spread too, but it would also erase everything the last two lessons
captured only partially.

On a job, containment is the moment the incident stops getting worse, and the
account you write afterwards is what lets someone else pick up the case. On
Pridwen you rehearse the commands on your own host, where isolating it for a
minute costs nothing, and then on a Rocky 9 Range host you own, arriving in
milestone M4, where the scenario is graded on the timeline you hand in.

## Words you'll meet

- **containment**: stopping an incident from spreading, without yet cleaning it up.
- **panic mode**: a firewalld state that drops every packet in and out, immediately.
- **firewalld**: the firewall service on Pridwen and Rocky; its default zone here is `drop`.
- **lock an account**: make its password unusable so no one can log in with it, without deleting it.
- **terminate a session**: end a login and the processes under it.
- **account** (the noun for a report): an ordered record of what happened and what you did, with times.

## How it works

Restating the essential from the Firewall node: firewalld sorts interfaces into
zones and the `drop` zone answers nothing unsolicited. Panic mode goes further
and drops everything, including replies to connections the host itself opened.
It is one command each way.

```
{user}@{host}:~$ sudo firewall-cmd --panic-on
success
{user}@{host}:~$ sudo firewall-cmd --query-panic
yes
{user}@{host}:~$ sudo ss -tnp state established
Recv-Q Send-Q Local Address:Port      Peer Address:Port     Process
0      0      192.168.122.15:38874    203.0.113.9:4444      users:(("bash",pid=9917,fd=3))
```

`--panic-on` turns it on and prints `success`; `--query-panic` confirms with
`yes`. The established connection is still listed, which is the point: the
socket exists in memory and the process is alive, but no packets pass, so the
other end is talking to a wall. Nothing about the evidence changed. On a Range
host reached over SSH, panic mode cuts your own session too, so run it from the
console the Range provides, not from a remote shell. `--panic-off` restores
normal filtering when the investigation allows.

If a specific account is the way in, close that path. `passwd -l` (lock) puts a
`!` in front of the password hash in `/etc/shadow` so the password no longer
matches anything, without removing the account or its files. `loginctl
terminate-user` ends every session that user has and the processes under them.

```
{user}@{host}:~$ sudo passwd -l webadmin
Locking password for user webadmin.
passwd: Success
{user}@{host}:~$ sudo passwd -S webadmin
webadmin LK 2026-09-07 0 99999 7 -1 (Password locked.)
{user}@{host}:~$ sudo loginctl terminate-user webadmin
{user}@{host}:~$ loginctl list-sessions | grep webadmin
{user}@{host}:~$
```

`passwd -S` (status) reads back: the account name, `LK` for locked (`PS` would
be a usable password), the date it last changed, and the ageing fields. The
empty result from `grep webadmin` after terminating confirms no session remains.
Locking is reversible with `passwd -u`, which is why it is preferred to
`userdel` during an incident: the home directory and its evidence stay where
they are. Note that a locked password does not block SSH keys; on a Range host,
check `{home}` of the account for `.ssh/authorized_keys` too.

Now the account, in the report sense. Take the captures and the notes file from
the last lesson and assemble one ordered timeline, with what the intruder did
and what you did in the same list, each line marked with its source.

```
{user}@{host}:~$ cat {home}/ir/2026-09-07-1118-timeline.txt
10:58:31  journal   sshd: Accepted password for webadmin from 203.0.113.9
10:59:04  ss        bash pid 9917 established to 203.0.113.9:4444
11:18:00  me        captured ps, ss, sessions, journal to ir/2026-09-07-1118-*
11:24:10  me        firewall-cmd --panic-on; query-panic yes
11:25:02  me        passwd -l webadmin; loginctl terminate-user webadmin
```

Two kinds of line share the list: findings from a log or a capture, and your own
actions marked `me`. Both carry a time. A reader can follow it top to bottom and
see when you knew what and when you acted, and can go back to the named capture
file to check any line. That readability is the deliverable. Contain to stop the
bleeding, then write it down.

## When it goes wrong

Your SSH session to a Range host freezes right after `--panic-on`. That is panic
mode working; it dropped your packets too. Use the console the Range provides
for that host, run `sudo firewall-cmd --panic-off`, and next time run panic mode
from the console.

`passwd: Unknown user name 'webadmin'.` The account does not exist on this host.
Your own Pridwen host has no `webadmin`; the example is a Range account. Check
`getent passwd` for the real name.

`Could not terminate user: No such process` from `loginctl`. The user has no
sessions, which after a lock is the result you wanted. Nothing to fix.

## Try it

1. On your own host, run `sudo firewall-cmd --panic-on`, then `sudo firewall-cmd --query-panic`. Try `ping -c 1 1.1.1.1` and watch it fail.
2. Run `sudo ss -tnp state established` while in panic mode and note that existing sockets are still listed.
3. Run `sudo firewall-cmd --panic-off` and `ping -c 1 1.1.1.1` again to confirm the network is back.
4. On a Range host with a suspect account, run `sudo passwd -l <name>`, `sudo passwd -S <name>`, and `sudo loginctl terminate-user <name>`.
5. Assemble a five-line timeline file from your captures and notes, mixing findings and `me` lines, each with a time and a source.
6. Explain in one sentence why isolation is preferred over powering the host off.

## Remember

- `firewall-cmd --panic-on` isolates a host but keeps its memory, processes and sockets alive for study.
- `passwd -l` plus `loginctl terminate-user` closes an account as the way in without deleting evidence.
- The deliverable is one ordered timeline that lists the intruder's actions and yours, each with a time and a source.
