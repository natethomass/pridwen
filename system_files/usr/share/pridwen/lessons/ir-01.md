# The first hour

When a Range host starts behaving strangely, the first hour has a shape: find out
who and what is on the machine, preserve what you see, and decide whether to
isolate it. Panic and a hasty reboot both destroy the very evidence you need, so
the first discipline is to slow down and observe.

Start with the live picture. `w` and `loginctl list-sessions` show who is logged
in; a session you cannot explain is the first thread. `ps aux` and `sudo ss -tnp
state established` show what is running and what it is talking to. Write down what
you find as you go, because memory blurs under pressure.

```
$ loginctl list-sessions
$ sudo ss -tnp state established
$ ps -eo pid,user,etime,cmd --sort=start_time | tail
```

The instinct to reboot and make it stop is the one to resist: a reboot clears
memory, running processes, and open sockets, which are your evidence. So is
killing the suspicious process before you have looked at what it is connected to.
The goal of the first hour is not to fix, it is to understand enough to act
without destroying the record, which the next lessons build on.

## Try it

1. On a Range host, list sessions and identify who is logged in.
2. Capture established connections and note any unfamiliar destination.
3. List processes by start time and pick out the most recent unexpected one.
4. Explain what a reboot would destroy that you have not yet recorded.
