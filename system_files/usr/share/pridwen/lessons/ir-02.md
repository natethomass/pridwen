# Preserve before you change

Everything you do to a live host changes it, so response means capturing state
before you alter it, in an order that keeps the most fragile evidence first.
Memory and running state vanish on reboot; disk survives. So you record the
volatile things first.

A minimal capture on a Range host is the process list, the network connections,
the logged-in users, and the recent journal, saved to a file with a timestamp.
Note the time and your own actions too, so later you can tell your footprints
from the intruder's. Only after capturing do you consider stopping anything.

```
$ ts=$(date +%F-%H%M)
$ ps auxww         > ~/ir/$ts-ps.txt
$ sudo ss -tanp    > ~/ir/$ts-ss.txt
$ loginctl list-sessions > ~/ir/$ts-sessions.txt
$ journalctl --since -2h > ~/ir/$ts-journal.txt
```

With that in hand you can afford to look closer at a suspect process, follow its
connections, and read what it touched, knowing the original picture is saved. The
same order applies whether the scenario is a compromised web-01 or a real
machine: volatile first, disk later, and a written record of your own steps
throughout, so the investigation itself does not muddy the evidence it depends on.

## Try it

1. On a Range host, write a short capture of ps, ss, sessions and the journal to files.
2. Timestamp the files and note the time you started.
3. Only then inspect one suspect process in more detail.
4. Explain the order of volatility and why memory comes before disk.
