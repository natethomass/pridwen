# Zones and the drop zone

firewalld organises rules into zones, each a named set of what is allowed for
interfaces or sources assigned to it. A packet is handled by the zone its
interface belongs to. Pridwen boots into the `drop` zone, the strictest default:
unsolicited inbound packets are discarded silently, while outbound traffic is
open.

Reading the firewall never changes it. `sudo firewall-cmd --get-active-zones`
shows which zone is in force, `--get-default-zone` shows the default, and
`--list-all` shows everything that zone permits. All of these need `sudo` because
firewalld answers only root over its D-Bus interface.

```
$ sudo firewall-cmd --get-default-zone
drop
$ sudo firewall-cmd --list-all
drop (active)
  target: DROP
  services:
  ports:
```

An empty services-and-ports list in the drop zone means exactly what it says:
nothing inbound is allowed except replies to connections you started. That is
what makes it safe to run a test server on a laptop that joins untrusted
networks, because the ports in `ss -tlnp` are not reachable from outside until
you open them on purpose. The next lesson covers opening exactly one thing.

## Try it

1. Run `sudo firewall-cmd --get-active-zones` and read the active zone.
2. Run `sudo firewall-cmd --list-all` and confirm the drop zone allows little.
3. Run `sudo firewall-cmd --get-zones` and read the names of the others.
4. Explain why the drop zone makes a listening service unreachable from outside.
