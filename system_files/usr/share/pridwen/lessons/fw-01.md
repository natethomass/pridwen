# Zones and the drop zone

A firewall decides which network packets may reach the programs on your machine.
On Fedora the firewall is managed by **firewalld**, a service that organises its
rules into **zones**. A zone is a named set of what is allowed for the network
interfaces or source addresses assigned to it: the `public` zone allows a few
services, the `trusted` zone allows everything, and the `drop` zone allows
nothing inbound. Each interface belongs to exactly one zone, and a packet
arriving on that interface is judged by that zone's rules.

Pridwen boots into the `drop` zone as its default. That is the strictest
choice: any packet that arrives uninvited is discarded silently, without even a
"closed" reply, while everything you start yourself (a web page, a package
download, a video call) works normally because replies to your own connections
are always allowed. A laptop joins coffee-shop and hotel networks where every
other device is a stranger, and the drop zone means a test server you forgot
about is not reachable from those strangers. Understanding zones is the RHCSA
firewall objective in one idea, and reading them is where every firewall
question starts.

## Words you'll meet

- **firewalld**: the daemon that owns the firewall rules on Fedora and turns zones into kernel rules.
- **`firewall-cmd`**: the command-line client that asks firewalld questions and gives it instructions.
- **zone**: a named policy (what is allowed in) applied to the interfaces or sources assigned to it.
- **default zone**: the zone an interface gets when nothing assigns it elsewhere; on Pridwen, `drop`.
- **active zone**: a zone that currently has an interface or source assigned, so it is actually judging packets.
- **target**: what a zone does with packets nothing else matched; `DROP` discards silently, `REJECT` sends a refusal, `ACCEPT` lets them in.
- **service**: a named shorthand for a port and protocol, like `ssh` for 22/tcp or `http` for 80/tcp.
- **inbound and outbound**: packets arriving at your machine from the network versus packets your machine sends out.
- **D-Bus**: the message bus that `firewall-cmd` uses to talk to firewalld; it only accepts root.

## How it works

Reading the firewall never changes it, so start there. Every `firewall-cmd`
call needs `sudo`, even for reads, because firewalld answers only root over
D-Bus. `--get-default-zone` prints the zone new interfaces fall into.

```
{user}@{host}:~$ sudo firewall-cmd --get-default-zone
drop
```

One word, `drop`. `--get-active-zones` shows which zones are actually judging
traffic and which interfaces belong to them.

```
{user}@{host}:~$ sudo firewall-cmd --get-active-zones
drop
  interfaces: wlp2s0
```

The first line is the zone name; the indented line lists the interfaces in it.
`wlp2s0` is a wireless card (the name is assigned by the kernel; an Ethernet
port might be `enp0s3`). If you see only that, every packet arriving from the
network is judged by the drop zone. `--list-all` prints everything the active
zone permits.

```
{user}@{host}:~$ sudo firewall-cmd --list-all
drop (active)
  target: DROP
  ingress-priority: 0
  egress-priority: 0
  icmp-block-inversion: no
  interfaces: wlp2s0
  sources:
  services:
  ports:
  protocols:
  forward: yes
  masquerade: no
  forward-ports:
  source-ports:
  icmp-blocks:
  rich rules:
```

Read the lines that matter. `target: DROP` is what happens to anything not
listed below: it is thrown away without a reply. `services:` and `ports:` are
both empty, so nothing is listed. An empty services-and-ports list in the drop
zone means exactly what it says: nothing inbound is allowed except replies to
connections you started. `forward: yes` and `masquerade: no` concern routing
traffic for other machines and do not apply to a laptop.

Compare that with what is listening. `ss -tlnp` (sockets: `-t` TCP, `-l`
listening, `-n` numeric ports, `-p` the process) shows what programs are
waiting for connections.

```
{user}@{host}:~$ ss -tlnp
State   Recv-Q  Send-Q   Local Address:Port   Peer Address:Port  Process
LISTEN  0       4096         127.0.0.1:53          0.0.0.0:*
LISTEN  0       128            0.0.0.0:8080        0.0.0.0:*      users:(("python3",pid=6120,fd=3))
```

The `Local Address:Port` column is where each program listens. `127.0.0.1:53`
is the local DNS resolver, reachable only from this machine. `0.0.0.0:8080` is a
test server that would accept connections from anyone, but the drop zone stands
in front of it, so from another machine port 8080 looks like it does not exist.
That is what makes the drop zone safe: a listening program is not a reachable
program until you open its port on purpose, which the next lesson covers.

Other zones exist for other situations. `--get-zones` lists them.

```
{user}@{host}:~$ sudo firewall-cmd --get-zones
block dmz drop external home internal nm-shared public trusted work
```

`public` is Fedora's usual default and allows `ssh` and `dhcpv6-client`;
`home` and `work` trust a bit more; `trusted` allows everything and is only for
a network you fully control. Pridwen chose `drop` so that allowing anything is
always a decision you made, never a default you inherited.

## When it goes wrong

`Authorization failed.` followed by `Make sure polkit agent is running or run
the application as superuser.` means you ran `firewall-cmd` without `sudo`.
firewalld refuses non-root callers even for reads; put `sudo` in front.

`Error: INVALID_ZONE: coffee` means the zone name you typed does not exist.
`sudo firewall-cmd --get-zones` lists the real names; Pridwen's active one is
`drop`.

`FirewallD is not running` means the daemon has been stopped. That is the one
state worse than any single open port, because every socket in `ss -tlnp` is
now reachable. `sudo systemctl start firewalld` brings it back; the third lesson
explains why stopping it is the wrong fix for an unreachable service.
`pridwen why` after any of these repeats the fix under the error.

## Try it

1. Type `sudo firewall-cmd --get-default-zone` and confirm it prints `drop`.
2. Type `sudo firewall-cmd --get-active-zones` and write down the interface name listed under `drop`.
3. Type `sudo firewall-cmd --list-all` and find `target: DROP`, then confirm `services:` and `ports:` are empty.
4. Type `ss -tlnp` and note which addresses are `127.0.0.1` (local only) and which are `0.0.0.0` (would be reachable if the firewall allowed it).
5. Type `sudo firewall-cmd --get-zones` and read the names of the other zones.
6. Type `sudo firewall-cmd --list-all --zone=public` and compare its `services:` line with the drop zone's.

## Remember

- A zone is a named policy; the interface's zone judges every inbound packet, and Pridwen's default is `drop`.
- `target: DROP` with empty `services:` and `ports:` means nothing inbound is allowed except replies to what you started.
- Every `firewall-cmd` needs `sudo`; reading with `--get-active-zones` and `--list-all` never changes anything.
