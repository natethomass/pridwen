# Opening one thing

The previous lesson showed that Pridwen's drop zone allows nothing inbound, so
a program listening on a port is invisible from the network until you open that
port. When a service genuinely needs to accept connections, you open exactly its
port or its named service, and nothing more. Opening one thing at a time keeps
the surface a scanner sees as small as the job requires, and it keeps you able
to say, for every open port, why it is open.

firewalld keeps two copies of its configuration at once: the **runtime** rules,
which the kernel is using this second, and the **permanent** rules, which are
saved on disk and loaded at the next reload or boot. The safe rhythm is to test
with a runtime change, confirm it does what you meant, and only then save it.
This is the rhythm the RHCSA expects, and it is the habit that stops a typo in
a firewall rule from surviving a reboot on a server you can no longer reach.

## Words you'll meet

- **runtime configuration**: the rules in effect now; changed instantly, lost at reload or reboot.
- **permanent configuration**: the rules saved under `/etc/firewalld/`; loaded at the next reload or boot.
- **`--reload`**: tells firewalld to throw away the runtime rules and load the permanent ones.
- **`--runtime-to-permanent`**: copies the current runtime rules into the permanent configuration.
- **service**: a firewalld definition that bundles one or more ports and protocols under a name, like `http` for 80/tcp.
- **port**: a number from 1 to 65535 that identifies which program a packet is for; always written with a protocol, like `8080/tcp`.
- **protocol**: `tcp` for connections (web, ssh) or `udp` for single packets (DNS, some games); the same number means different things on each.

## How it works

Say you started a test web server on port 80 and want a colleague on the same
network to see it. Add the `http` service to the active zone. With no
`--permanent` flag, this is a runtime change and takes effect immediately.

```
{user}@{host}:~$ sudo firewall-cmd --add-service=http
success
{user}@{host}:~$ sudo firewall-cmd --list-services
http
```

`success` is firewalld's whole answer when it did what you asked.
`--list-services` reads back the runtime list, and `http` is now on it. From
another machine, port 80 answers. If the change did something unexpected,
`sudo firewall-cmd --reload` throws away every runtime change and you are back
to the saved rules, which on Pridwen means back to nothing open.

When the runtime rule is right, keep it.

```
{user}@{host}:~$ sudo firewall-cmd --runtime-to-permanent
success
{user}@{host}:~$ sudo firewall-cmd --list-all --permanent | grep services
  services: http
```

`--runtime-to-permanent` copies what is live into the files under
`/etc/firewalld/zones/`. Adding `--permanent` to `--list-all` reads the saved
copy instead of the live one, and the `services:` line now shows `http` there
too.

The other order also works: write to the permanent configuration first, then
reload. A `--permanent` change is written to disk but does not touch the running
rules until `--reload`. Ports without a service name are opened with
`--add-port`, and the protocol is always part of the argument.

```
{user}@{host}:~$ sudo firewall-cmd --permanent --add-port=8080/tcp
success
{user}@{host}:~$ sudo firewall-cmd --list-ports

{user}@{host}:~$ sudo firewall-cmd --reload
success
{user}@{host}:~$ sudo firewall-cmd --list-ports
8080/tcp
```

Notice the empty line after the first `--list-ports`: the port was saved but
not yet live. After `--reload` it appears. This is the most common firewall
confusion there is, a permanent rule that was never reloaded, so read the live
list after every change. A range is written `8000-8100/tcp`, and a UDP port as
`5353/udp`.

Service names are looked up from definitions firewalld ships. `--get-services`
lists every name it knows, and `--info-service` shows what a name expands to.

```
{user}@{host}:~$ sudo firewall-cmd --info-service=http
http
  ports: 80/tcp
  protocols:
  source-ports:
  modules:
  destination:
  helpers:
```

`ports: 80/tcp` is what `--add-service=http` really opens. For anything that
has no definition, use `--add-port` with the number and protocol.

Closing is the mirror image. `--remove-service=http` and
`--remove-port=8080/tcp` take the runtime rule away; add `--permanent` and
`--reload`, or `--runtime-to-permanent`, to make the removal stick. The Coach
reminds you after a runtime-only add that the change will not survive a reboot,
and after a permanent-only add that it is not live yet; both hints are the two
copies talking.

## When it goes wrong

`Error: INVALID_SERVICE: web` means firewalld has no definition named `web`.
`sudo firewall-cmd --get-services` lists the real names (`http`, `https`,
`ssh`, `dns`, and about two hundred more); for anything else use
`--add-port=8080/tcp`.

`Error: INVALID_PORT: bad port (most likely missing protocol), correct syntax
is portid[-portid]/protocol` means you wrote `--add-port=8080` without `/tcp`
or `/udp`. The number alone is ambiguous, so firewalld refuses it.

`Warning: ALREADY_ENABLED: http` means the rule is already there; nothing
changed and nothing is wrong. Likewise `Warning: NOT_ENABLED` on a remove means
it was not there to begin with. `pridwen explain firewall-cmd` annotates the
flags when one is the question.

## Try it

1. On a Range host, type `sudo firewall-cmd --add-service=http` and expect `success`.
2. Type `sudo firewall-cmd --list-all` and find `http` on the `services:` line.
3. Type `sudo firewall-cmd --runtime-to-permanent`, then `sudo firewall-cmd --list-all --permanent` and confirm `http` is in the saved copy too.
4. Type `sudo firewall-cmd --permanent --add-port=8080/tcp`, then `sudo firewall-cmd --list-ports` and expect an empty line, because it is not live yet.
5. Type `sudo firewall-cmd --reload` then `sudo firewall-cmd --list-ports` and expect `8080/tcp`.
6. Type `sudo firewall-cmd --permanent --remove-service=http`, `sudo firewall-cmd --permanent --remove-port=8080/tcp`, and `sudo firewall-cmd --reload`; confirm `--list-all` is short again.

## Remember

- Runtime is now and vanishes at reload; permanent is saved and needs `--reload` to become live.
- Test at runtime, then `--runtime-to-permanent`; or `--permanent` then `--reload`; either way, read `--list-all` afterwards.
- Open one named service or one `port/protocol`, never a zone change or the whole firewall, and remove it when the job is done.
