# Opening one thing

When a service genuinely needs to accept connections, you open exactly its port
or its named service, and nothing more. firewalld keeps two configurations at
once: the runtime rules the kernel is using now, and the permanent rules saved on
disk. Testing with runtime and then saving is the safe rhythm.

A runtime change takes effect immediately and vanishes at the next reload or
reboot, which is perfect for trying something. `--runtime-to-permanent` saves the
live set once you are happy. A `--permanent` change writes to disk but does not
apply until `--reload`.

```
$ sudo firewall-cmd --add-service=http                 # runtime, test now
$ sudo firewall-cmd --runtime-to-permanent             # keep it
$ sudo firewall-cmd --permanent --add-port=8080/tcp    # for next reload
$ sudo firewall-cmd --reload
```

A service name like `http` or `ssh` is a firewalld shorthand for a port and
protocol; `--get-services` lists the known ones. For anything without a name,
open the port directly with `--add-port=8080/tcp`, always with the protocol, and
a range as `8000-8100/tcp`. The discipline of opening one service at a time keeps
the attack surface a scanner sees as small as the job requires.

## Try it

1. On a Range host, add a service at runtime and confirm it with `--list-all`.
2. Save it with `--runtime-to-permanent` and read `--list-all --permanent`.
3. Add a numeric port with its protocol, then `--reload`.
4. Remove what you added and confirm the list is short again.
